# 작업 관리는 GitHub Issues로

## 결론

작업 목록은 GitHub Issues에서 관리한다. PR 설명에 `Closes #이슈번호`를 넣어 merge할 때 이슈가 자동으로 닫히게 한다. v0.1의 `TODO.md`는 `docs/`에 기록으로 남긴다.

## 배경

v0.1은 `TODO.md`로 작업을 관리했다. 2026-10-23~24에 Jira를 연결해 시험했으나, GitHub 연결과 자동 규칙 설정에 사람이 할 일이 많았다.

## 검토한 대안

- `TODO.md`
- Jira (Scrum, GitHub for Jira, 자동 규칙)
- GitHub Issues

## 결정 이유

GitHub Issues는 저장소에 기본으로 있어 따로 연결할 것이 없다. merge하면 이슈가 자동으로 닫힌다. Agent도 `gh issue`로 이슈를 다룰 수 있다.

## 영향

branch 이름에 이슈 번호를 넣는다(D010). Jira 사이트와 연결은 나중을 위해 남겨 두고 쓰지 않는다.
