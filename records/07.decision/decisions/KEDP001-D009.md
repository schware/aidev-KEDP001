# Agent 운영과 규칙 파일

## 결론

KEDP는 역할별 Agent 구조를 사용한다.

```text
Common

TypeScript

Go

Rust

Database
```

프로젝트 소유자(사용자)는 작업 영역을 지정하여 Agent에게 업무를 요청한다.

Agent는 요청받은 영역만 작업한다.

최종 승인과 병합은 프로젝트 소유자가 담당한다.

프로젝트 규칙은 `.claude/` 폴더에서 관리한다.

```text
.claude/

CLAUDE.md
api.md
git.md
environment.md
```

v0.1의 `AGENTS.md` 는 기록 목적으로 `docs/` 에 보관한다.

---

## 배경

TypeScript, Go, Rust, PostgreSQL로 구성된 프로젝트에서는 역할별 책임 경계가 필요하다.

하나의 Agent가 모든 영역을 동시에 변경하면 변경 범위 추적과 검토가 어려워질 수 있다.

역할별 Agent를 구분하여 설계, 구현, 검토 범위를 명확하게 유지한다.

---

## 검토한 대안

### Agent 운영

- 하나의 Agent가 전체 작업 수행
- 역할별 Agent 분리

### 규칙 파일 구성

- AGENTS.md 단일 파일
- CLAUDE.md 단일 파일
- `.claude/` 폴더 구조

---

## 결정 이유

### 역할 분리

- 변경 범위 명확화
- 책임 경계 유지
- 영역별 전문성 확보

### 사용자 중심 운영

- 프로젝트 소유자가 작업을 통제
- 필요한 영역만 선택하여 작업 가능
- 의도하지 않은 변경 방지

### 규칙 파일 분리

- 관리 용이
- 규칙 재사용 가능
- 필요한 문서만 참조 가능

## 업무 요청 원칙

프로젝트 소유자는 대상 영역을 지정하여 요청한다.

예시

```text
TypeScript 작업 요청

Go 작업 요청

Rust 작업 요청

Database 작업 요청

Common 작업 요청
```

Agent는 요청받은 영역만 작업한다.

---

## 작업 제한

Agent는 요청받지 않은 영역을 변경하지 않는다.

예시

```text
TypeScript Agent

↓

Rust 수정 금지
```

```text
Go Agent

↓

DB 스키마 변경 금지
```

```text
Database Agent

↓

React 화면 수정 금지
```

영역을 넘어서는 변경이 필요한 경우 프로젝트 소유자에게 보고한다.

---

## 승인 원칙

Agent는 다음 역할만 수행한다.

```text
분석

설계

구현

제안
```

최종 결정은 프로젝트 소유자가 수행한다.

최종 승인과 병합은 프로젝트 소유자가 담당한다.
