# Agent 운영과 규칙 파일

## 결론

처음에는 Claude Code 하나로 역할을 차례대로 바꿔가며 진행한다. 프로젝트 규칙은 `.claude/CLAUDE.md`에 두고, API 키 규칙(`api.md`)과 Git 규칙(`git.md`)은 항상 함께 읽히게, 개발 환경(`environment.md`)은 필요할 때 읽게 나눈다. v0.1의 `AGENTS.md`는 `docs/`에 기록으로 남긴다.

## 배경

지금 작업은 앞 단계 결과가 있어야 다음을 할 수 있다. 규칙 파일이 길면 매번 읽는 양이 늘고 중요한 규칙이 묻힌다.

## 검토한 대안

- 운영: 여러 Agent 동시 / 하나로 차례대로
- 규칙 파일: `AGENTS.md` / 맨 위 `CLAUDE.md` 한 파일 / `.claude/` 안에서 나누기

## 결정 이유

동시에 해도 기다리는 시간이 많다. 규칙은 짧은 본문과 필요한 세부 파일로 나누는 편이 관리와 준수에 낫다. 맨 위 폴더도 깔끔해진다.

## 영향

다른 편집기의 AI는 `.claude/` 안의 규칙을 읽지 못할 수 있다. KEDP는 Claude Code를 쓰므로 문제없다.

## 미해결 질문

- 동시 진행으로 바꾸는 시점
- 프로젝트 소유자 검토 후 `decided` 전환 여부
