# API 키 보호 5겹

## 결론

API 키를 다섯 겹으로 보호한다. 1·3·4·5겹을 갖춘 뒤에 실제 키를 넣는다.

1. `.gitignore`로 `.env` 제외
2. Go 코드에서 기록할 때 키를 `***`로 가리기
3. commit 전 hook: `.env`의 실제 키 값 대조
4. commit 전 hook: gitleaks 검사
5. PR 자동 검사: gitleaks로 commit 기록 전체 검사

상세 절차는 `docs/key-protection.md`를 따른다.

## 배경

세 제공처 모두 키가 요청 주소에 들어가서 로그, 에러, 샘플에 남기 쉽다. Git은 한 번 올라간 기록을 기억한다.

## 검토한 대안

- `.gitignore`만
- hook까지
- hook + PR 자동 검사 + 코드에서 가리기

## 결정 이유

3겹은 주소 안의 키를 gitleaks가 못 알아볼 경우를 대비한다. 5겹은 hook이 없는 팀원의 실수도 잡는다. 2겹은 Git 밖(로그, 화면, 공유)으로 새는 길을 막는다.

## 영향

팀원은 clone 뒤 `git config core.hooksPath .githooks`와 gitleaks 설치가 필요하다. 키가 노출되면 재발급이 먼저다.

## 미해결 질문

- 공공데이터포털 키의 Encoding/Decoding 형태를 3겹이 모두 대조하도록 보강할지
- 프로젝트 소유자 검토 후 `decided` 전환 여부
