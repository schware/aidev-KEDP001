# 관리자 화면: 키는 다루지 않고, 설정은 DB에, 인증은 계정+비밀번호 파일로

## 결론

1. **API 키는 화면에서 다루지 않는다.** API 관리 화면은 연결 상태, 키 설정 여부(설정됨/안 됨), 마지막 수집 일시만 보여준다. 키는 서버 `.env`에서 소유자가 관리한다.
2. **지표 설정은 관리자 화면에서 한다.** 지표 추가, 노출과 순서, 수집 주기, 차트 기간, 관련 지표, 숫자·날짜 표시 형식을 Dashboard 관리 화면에서 정하고 DB에 저장한다.
3. **관리자 접근**은 지정 URL(`/admin`) + 허용 IP + 관리자 인증을 모두 만족해야 한다.
4. **관리자 인증**은 계정 + 비밀번호로 하고, 서버의 파일 하나로 관리한다. MVP에서는 더 발전시키지 않는다.
5. 허용 IP, 계정, 비밀번호 같은 실제 값은 저장소에 쓰지 않는다.

## 배경

웹 화면에서 키를 입력받으면 암호화 저장, 인증 강화, 접근 기록 등 보안 설계가 훨씬 커진다. 지표 주기, 기간, 관련 지표 같은 세부 값은 한 번 정하고 끝나는 것이 아니라 다시 보고 고칠 수 있어야 한다.

## 검토한 대안

- 키: 화면에서 등록·수정 / 상태만 표시
- 지표 설정: 지표마다 고정 / 관리자 화면에서 설정
- 인증: 계정+비밀번호 파일 / 사용자 DB / 외부 로그인

## 결정 이유

키를 화면에서 다루지 않으면 KEDP001-D012(키 보호 5겹)를 그대로 지킬 수 있다. 지표 설정을 관리자 화면에 두면 나중에 다시 보고 수정할 수 있다. 인증은 MVP에서 가장 단순한 방법으로 한다.

## 영향

DB에 관리자 설정을 저장할 구조가 필요하다. 인증 파일은 `.env`처럼 Git에 올리지 않는다.
