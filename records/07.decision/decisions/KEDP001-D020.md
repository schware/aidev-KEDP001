# MVP 운영 최소 기준: 장애 대비는 미루고, 백업은 스크립트, 배포는 SSH

## 결론

1. **장애**: Rust 서버가 멈추면 Go의 처리도 멈춘다. 서버 상태 확인이나 재시작 같은 장애 대비는 MVP 이후에 다룬다.
2. **백업**: PostgreSQL 백업은 백업 정책을 문서로 정하고, 백업 실행은 스크립트로 만들어 crontab에서 관리한다.
3. **배포**: 개발 서버(dell-debian)에서 SSH 키로 실행 서버(macpro-debian)에 접속해 배포한다. 서버 주소와 키 같은 실제 값은 저장소에 쓰지 않고, 개발 서버의 SSH 설정에만 둔다.

## 배경

장애 대비를 위해 상태 확인 프로그램을 더하면, 그 프로그램이 멈추는 경우를 또 대비해야 해서 MVP가 커진다.

## 검토한 대안

- 장애: 상태 확인·자동 재시작을 MVP에 포함 / MVP 이후
- 백업: 수동 / 스크립트 + crontab
- 배포: 수동 복사 / SSH로 원격 실행

## 결정 이유

MVP는 동작하는 것을 먼저 만들고, 운영 안정성은 그다음에 보강한다.

## 영향

MVP 기간에는 서버가 멈추면 사람이 다시 실행한다.
