# Git 작업 방식

## 결론

main에서 직접 작업하지 않고, 작업마다 `담당/이슈번호-작업내용` branch를 만들어 PR로 합친다. commit, push, PR, merge는 사람이 한다. 사람이 요청하면 Agent가 PR 생성까지 할 수 있고, merge는 하지 않는다. merge는 squash로 하고, PR 설명에 `Closes #이슈번호`를 넣는다.

## 배경

팀(3~5인) 작업 방식을 처음부터 연습한다. 사람이 결과를 확인하고 반영하는 단계가 필요하다.

## 검토한 대안

- commit: Agent도 / 사람만
- 반영: main 직접 / branch + PR
- 도구: GitHub Desktop / gh와 GitHub 웹

## 결정 이유

사람이 commit하고 merge하는 것이 곧 검토가 된다. main은 항상 확인을 거친 상태로 남는다. 서로 믿음이 쌓이면 Agent에게 맡기는 범위를 넓힌다.

## 영향

merge 뒤 `git switch main`과 `git pull`을 잊지 않아야 한다.

## 미해결 질문

- 프로젝트 소유자 검토 후 `decided` 전환 여부
