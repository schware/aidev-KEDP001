# 실제 API 조사 이후 DB 스키마를 결정

## 결론

대표 지표의 실제 API 응답과 key, value, 단위, 기간, 분류 및 논리 key를 확인한 이후 물리 DB 스키마를 설계한다.

## 배경

ECOS와 KOSIS의 구조가 다르고 KOSIS는 다차원 분류를 포함할 수 있어 사전 스키마 확정 시 재설계 위험이 있다.

## 검토한 대안

- 사전에 범용 테이블 확정
- 제공처별 테이블 선확정
- 대표 응답 조사 후 저장 방식 결정

## 결정 이유

실제 데이터를 근거로 제공처별, 범용, 혼합 또는 Staging-Result 구조를 비교하는 것이 안전하다.

## 영향

DB Agent는 조사 전 DDL과 migration을 작성하지 않는다. Go Agent는 샘플을 확보하고 Rust Agent는 구조를 분석한다.

## 미해결 질문

- 프로젝트 소유자 검토 후 `decided` 전환 여부를 확정한다.
