# 지표 확장: 핵심 세트 중 ECOS·KOSIS 지표만 추가하고, 지표에 구분 9개를 붙인다

## 결론

1. **이번 범위는 핵심 세트 중 ECOS·KOSIS 지표만이다.** 아래 "추가 후보" 목록에 있는 지표다. 새 제공처(관세청, 국토교통부 실거래, 재정), 차원(국가·지역·품목), 파생지표(내부 계산값)는 이번에 하지 않는다.
2. **증감률은 공식값만 넣는다.** ECOS·KOSIS가 증감률을 직접 주지 않으면 그 지표는 이번 범위에서 뺀다. 내부에서 계산하지 않는다.
3. **지표 id 규칙은 지금 방식을 유지한다.** `{제공처}-{영문 이름}`, 소문자·숫자·`-`만 쓴다(예: `ecos-base-rate`, `ecos-gdp-real-sa`). 이미 있는 id는 바꾸지 않는다.
4. **지표마다 구분 하나를 붙인다.** 구분은 아래 9개로 고정한다. 관리자는 지표를 추가·수정할 때 이 중 하나를 고른다. 구분을 추가·수정하는 화면은 만들지 않는다.
5. **메인 화면은 구분별로 묶어 보여 준다.** 구분 순서는 아래 표의 순서다. 구분 안의 카드 순서는 지금의 노출 순서를 쓴다.

## 구분

| 순서 | code | 이름 | 지금 있는 지표 |
| --- | --- | --- | --- |
| 1 | `growth` | 성장·경기 | GDP |
| 2 | `price` | 물가 | 소비자물가지수 |
| 3 | `labor` | 고용·소득 | 고용률 |
| 4 | `money` | 금리·통화 | 기준금리 |
| 5 | `credit` | 부채·금융안정 | |
| 6 | `external` | 대외경제 | 외환보유액 |
| 7 | `housing` | 주택 | |
| 8 | `population` | 인구 | 총인구, 출생아 수 |
| 9 | `market` | 금융시장 | KODEX 200, KODEX 레버리지, KODEX 인버스 |

KOSPI, KOSPI200, 전산업 사업체 수는 지금처럼 관리자 화면의 지표 추가로 넣는다. KOSPI, KOSPI200은 `market`이다.

## 추가 후보

통계표·항목 코드는 확인하지 않았다. Go 역할이 샘플로 확인한 뒤 `specification/10.indicators/`에 적는다. ECOS·KOSIS에 없으면 뺀다.

- **성장·경기:** 명목 GDP, 실질 GDP(원계열), 실질 GDP(계절조정), 실질 GDP 전기 대비 성장률, 실질 GDP 전년 동기 대비 성장률, 전산업생산지수(계절조정), 제조업생산지수(계절조정), 서비스업생산지수(계절조정), 소매판매액지수(계절조정), 설비투자지수
- **물가:** 소비자물가지수 전년 동월 대비, 생활물가지수 전년 동월 대비, 신선식품지수 전년 동월 대비, 근원물가(식료품·에너지 제외) 전년 동월 대비, 생산자물가지수 전년 동월 대비, 수입물가지수(원화) 전년 동월 대비
- **고용·소득:** 취업자 수, 실업률, 경제활동참가율, 청년 고용률, 명목임금(월), 실질임금(월)
- **금리·통화:** 국고채 3년, 국고채 10년, 회사채 3년 AA-, 예금은행 대출금리(신규취급액), 예금은행 수신금리(신규취급액), M2 평잔(원계열)
- **부채·금융안정:** 가계신용, 주택담보대출, 기업신용, 개인사업자 대출, 은행 연체율
- **대외경제:** 원·달러 환율, 경상수지, 수출액, 수입액, 무역수지, 일평균 수출액
- **주택:** 주택매매가격지수, 주택전세가격지수, 미분양 주택
- **인구:** 생산가능인구(15~64세), 65세 이상 인구 비율

이번 범위에서 뺀 것: 아파트 매매 거래량(국토교통부 실거래를 건별로 모아 집계해야 한다).

## 배경

MVP(지표 10개, 사용자 화면, 관리자 화면, 배포, 방문자 수)는 2026-11-01에 끝났다. 소유자가 대한민국 거시경제 지표 설계서(약 200개 KEY, 2026-11-02)를 바탕으로 지표를 늘리려 한다.

설계서는 지금 구조와 다른 곳이 있다.

- KEY 형식이 `kr.growth.gdp.real`(점, 밑줄)이고 제공처 이름을 뺀다. 지금 `indicator.id`는 소문자·숫자·`-`만 받고 화면 주소에도 쓴다.
- 차원, 파생지표, 메타데이터(`value_type`, `adjustment`, `data_origin` 등), 주기 `W`·`E`를 지금 DB가 받지 않는다.
- 관세청, 국토교통부 실거래 같은 제공처를 지금 수집기가 부르지 않는다.

지표가 50개 안팎으로 늘면 검색 없는 메인 화면에서 찾기 어렵다(50.web 1장). 그래서 구분이 필요하다.

## 검토한 대안

- 범위: 설계서 전체 / 핵심 세트 전체 / 핵심 세트 중 ECOS·KOSIS만
- id: 지금 방식 유지 / 설계서 방식(제공처 이름 빼기, 이미 있는 id도 변경)
- 구분: 고정 목록 / 관리자가 구분을 만들고 고침 / 구분 없이 노출 순서만

## 결정 이유

- ECOS·KOSIS는 수집기, 정규화, 샘플 도구가 이미 있다. 지표를 행으로 추가하고 코드만 확인하면 된다.
- id를 바꾸면 화면 주소, 관측값, 관련 지표 연결을 모두 고쳐야 한다. 제공처가 바뀌는 일은 드물고, 그때 id 하나만 바꾸면 된다.
- 구분 목록은 자주 바뀌지 않는다. 고정하면 관리 화면과 API가 늘지 않는다.
- 설계서 19장은 개별 시세를 제외하지만, KODEX 3종은 MVP에서 지표 추가 시험용으로 넣은 것이라 `market`으로 모아 남긴다.

## 영향

- **Database:** `category` 표(code, name, sort_order)를 만들고 9개를 넣는다. `indicator`에 `category_code`(NOT NULL, `category` 참조)를 추가한다. 지금 있는 지표는 같은 migration에서 위 표대로 채운다.
- **Go:** 카드 목록과 상세 응답에 `category`(code, name)를 넣는다. 관리자 지표 추가·수정에서 `category`를 받는다. `GET /api/admin/categories`를 추가한다. 40.api를 고친다.
- **TypeScript:** 메인 화면을 구분별로 묶는다. 관리자 지표 추가·편집에 구분 선택 칸, Dashboard 목록에 구분 칸을 넣는다. 50.web을 고친다.
- **지표 추가:** 추가 후보의 코드를 샘플로 확인한 뒤 관리자 화면(또는 migration)으로 넣는다.
