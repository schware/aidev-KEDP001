# TypeScript, Go, Rust, PostgreSQL과 Docker를 사용하고 Go–Rust는 gRPC로 연결

## 결론

TypeScript는 웹 화면에 사용한다.
Go는 외부 API 수집과 서비스 API 제공에 사용한다.
Rust는 데이터 검증, 정규화, 처리에 사용한다.
PostgreSQL은 데이터 저장과 조회에 사용한다.
Go와 Rust는 gRPC로 통신한다.
전체 시스템의 실행과 배포는 Docker를 사용한다.

## 배경

AI Agent를 기술 영역별로 분리하면서 각 언어의 책임 경계와 Go–Rust 연결 방식을 정할 필요가 있다.
또한 개발 환경과 실행 환경을 일관되게 유지하기 위해 Docker 기반 실행 구조를 함께 결정한다.
연결 방식에 따라 저장소 구조, 도구, Docker 구성이 달라진다.

## 검토한 대안

### 언어

- TypeScript와 Go만 사용
- TypeScript, Go, Rust, PostgreSQL 사용

### Go–Rust 연결

- 명령 실행
- Rust 서버 + HTTP/JSON
- Rust 서버 + gRPC
- DB를 통해 주고받기
- Rust를 Go 안에 넣기(FFI)

### 실행 방식
- Docker만


## 결정 이유

### TypeScript

- 웹 화면 개발 표준
- React 생태계 활용 가능
- 유지보수 용이

### Go

- 외부 API 수집에 적합
- 서비스 API 구현이 단순
- 경량 서비스 운영 가능

### Rust

- 안전한 데이터 처리
- 검증과 정규화 역할 분리
- 향후 데이터 처리 확장 가능

### PostgreSQL

- 장기 운영 가능
- 시계열 데이터 관리 가능
- 향후 BI 및 AI 연동 가능

### gRPC

- Go와 Rust 간 계약(.proto) 관리 가능
- 타입 안정성 확보
- 구조 변경 추적 가능

### Docker

- 개발 환경과 실행 환경 차이를 줄일 수 있다.
- 서비스 단위 배포가 가능하다.
- Docker Compose 기반 전체 실행이 가능하다.

## Docker 원칙

개발은 Linux 개발 서버에서 직접 실행한다.

배포와 통합 테스트는 Docker Compose를 사용한다.

각 서비스는 독립 컨테이너로 실행 가능해야 한다.

환경설정은 환경변수로 주입한다.

API Key는 Docker 이미지에 포함하지 않는다.
