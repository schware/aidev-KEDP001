# TypeScript, Go, Rust와 SQL을 사용하고 Go–Rust는 gRPC로 연결

## 결론

TypeScript는 웹, Go는 외부 API와 서비스 API, Rust는 데이터 처리, SQL은 PostgreSQL 저장과 조회에 사용한다. Rust는 작은 서버로 띄우고, Go가 gRPC로 호출한다.

## 배경

AI Agent를 기술 영역별로 분리하면서 각 언어의 책임 경계와 Go–Rust 연결 방식을 정할 필요가 있다. 연결 방식에 따라 저장소 구조, 도구, Docker 구성이 달라진다.

## 검토한 대안

- 언어: TypeScript와 Go만 / TypeScript, Go, Rust와 SQL / 단일 언어
- Go–Rust 연결: 명령 실행 / Rust 서버 + HTTP·JSON / Rust 서버 + gRPC / DB를 통해 주고받기 / Rust를 Go 안에 넣기(FFI)

## 결정 이유

Rust를 서버로 두면 Docker에서 Go와 깔끔하게 나눌 수 있다. gRPC는 `.proto` 약속서로 주고받는 형식을 엄격하게 정한다. 소유자가 Go와 Rust를 직접 익히는 학습 목적도 있다. (AI 추천은 조사 단계의 명령 실행과 HTTP·JSON이었다.)

## 영향

`b-proto/` 폴더와 gRPC 도구(protoc, protoc-gen-go, protoc-gen-go-grpc, grpcurl)가 필요하다. Rust 서버의 상태 확인이 필요하다. Rust의 실제 처리 범위는 API 조사 이후 구체화한다.

## 미해결 질문

- Rust 서버가 멈췄을 때 Go의 동작
- 프로젝트 소유자 검토 후 `decided` 전환 여부
